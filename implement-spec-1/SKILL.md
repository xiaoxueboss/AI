读取`../implement-spec/SKILL.md` 的最新内容并遵循其工作流程。以下规则优先于其中冲突的分支和工作区规则：

- 在当前 Git 仓库根目录的 `临时工作区` 下，为每个新工作区使用独立且不冲突的子目录；无写入权限时停止并询问用户新位置。
- 以仓库已有的 `master` 为开发基准和最终交付分支；没有 `master` 时使用当前分支。跳过原流程中新建集成分支的步骤；原流程后续所称的集成分支均指本次选定的交付分支。需要隔离时，从交付分支创建临时分支和工作区；临时分支与 `master` 并列，默认使用 `codex/功能名`，项目有其他前缀要求时遵循项目规则，不使用 `master/功能名`。分支名称的用途部分和工作区子目录用不超过 15 个汉字简述用途，冲突时加数字区分。
- 验证后将成果安全整合到交付分支，再清理本次创建且已整合的临时工作区和分支，使本次流程不遗留额外分支。不删除原有分支；保护用户已有改动，不将无关改动纳入提交。整合或清理受阻时保留成果并说明。
